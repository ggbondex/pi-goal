# goal-loop

自主目标循环扩展：给 pi 一个目标，它停下来时由 AI 判定目标是否真的完成；没完成就把目标再发一遍，直到完成、受阻、或达到续跑上限。

## 为什么

pi 做完一个小项就会停下来问"要不要继续"。跑长计划（例如 `docs/IMPLEMENTATION_PLAN.md` 的 29 个切片）时得一直盯着回车。
这个扩展把"要不要继续"的判断交给一个判定模型，而不是交给人。

## 用法

```
/goal 按 docs/IMPLEMENTATION_PLAN.md 从当前进度顺序完成，直到所有切片的判定都跑通过
```

只想给个目标、直接开跑（不规划）：

```
/goal <目标>
```

想先规划出「目标 + 有序里程碑」再开跑：

```
/goal plan 给助手加记笔记能力
/goal plan 完成 docs/IMPLEMENTATION_PLAN.md
/goal plan @docs/IMPLEMENTATION_PLAN.md        # 显式指定计划文件
```

之后：

```
/goal                 查看状态（有计划时显示里程碑看板）
/goal plan            用法
/goal stop            停止循环（保留目标，可 resume）
/goal resume          从断点接着跑
/goal clear           彻底清除目标（不再记忆，含重启/切分支后）
/goal model <spec>    指定判定/规划模型：auto | provider/modelId | modelId
/goal max <n>         续跑上限（默认 15）
/goal help            用法
```

一次性默认值可用环境变量：`PI_GOAL_MAX`、`PI_GOAL_MODEL`、`PI_GOAL_RETRY_BASE_MS`（错误冷却退避基数，默认 60s）、`PI_GOAL_JUDGE_TIMEOUT_MS`（判定调用超时，默认 90s）。

## 每一轮发生什么

1. `/goal <目标>` 把目标当作普通用户消息发出，agent 开始干活。
2. 当这轮 agent 真正要收尾时（`agent_before_settle`），扩展把目标 + 当前对话记录交给判定模型，要求它只返回一个 JSON：
   `{"done": bool, "blocked": bool, "reason": "...", "next": "..."}`。
3. 判定为 `done` → 停止，并提示"目标已完成"。
   `blocked` → **暂停**（不是结束）：把"需要你决定什么"告诉你；你直接回答即可，下一轮会自动恢复并接着跑。想彻底停下用 `/goal stop`。
   都不是 → 注入一条续跑消息（含判定原因、下一步、以及**原始目标原文**），agent 继续。
4. **瞬时错误自愈**：provider 错误（429 限流、超时、掉线——用 pi 内置重试同一套判定）不会让循环静默停摆：扩展在收尾边界内退避冷却（60s 起指数、5min 封顶），最多自动重试 5 次（约 17 分钟），每次把失败那轮从上下文抠掉再续跑。预算烧完或错误非瞬时 → **暂停**：状态行显示「运行出错 · 等你答复」，你直接回话即自动恢复。判定调用有 90s 超时；判定失败也走同样的冷却重试，连续 3 次才停。
5. 硬上限保护：最多自动续跑 `max` 次；你在判定或干活时按 Esc 会直接停止循环。

判定提示词里专门写明：**agent 问"要不要继续"不算完成、也不算受阻**——这正是要修的行为。

## 计划模式（`/goal plan`，可选）

规划是**可选**的：只有显式敲 `/goal plan` 才走那套，普通 `/goal` 一个字不变。
`/goal plan <意图|@文件>` 让 pi **先调研仓库**（读合同、读测试、看真实存在哪些命令），再产出一份**冻结的**「目标 + 有序里程碑」。规划就是**一次普通的 pi turn，不限制工具**——只在提示词里要求「先别动手实现，这一步只出计划」。它打印看板并**等你确认**；你回一句「同意」就开始跑——**不需要再敲一次 `/goal plan`**，扩展用 `input` 事件接住那句普通回复（`同意` / `取消` / 任何修改意见，后者会带上去重新规划）。

规划提示词强制三件事：

- **每条里程碑是独立检查点**：`exit` 是一条**现在就跑得动、且不依赖后续里程碑**的命令，指向仓库里**真实存在**的检查（禁止编造测试名/脚本名）。
- **合起来覆盖完整差集**：不多一条（永远卡住的假里程碑），不少一条（漏活会让判定提前说完成）。
- **依赖有序**：不可逆的先（现在最便宜）、挡别人的先、能看见的最后。

- **调研不够就问**：规划若信息不足，会返回问题而不是硬编计划；你回答后它带答案重新规划（`needs_answers`）。
- **拿不准的点会单独、显眼地问你**：规划列进 `unknowns` 的点，扩展会在看板之后**另起一块**（最多 3 条、编号），以 pi 的 warning 样式渲染——不再埋在看板里面。你答一句它据此重新规划（最多自动追问一轮）。
- **产出要短、只输出 JSON**：提示词要求 `objective` 一句、`why` 一行、最终消息只有 JSON；看板也会把超出的 unknown 折叠起来，保证一屏。
- **不把原始 JSON 甩到会话里**：规划那一轮的 JSON 会被换成一行「（已生成计划，见下方看板）」，计划只由看板展示。
- **详细计划落一份文件**：里程碑是概要；正文（每片怎么做、动哪些文件、验收命令、决定与风险）由 pi 写到**插件自己的**文件 `.pi/goal-plans/<slug>.md`，看板上一行 `详细计划：<路径>` 指向它。重规划会重写这份文件。
- **里程碑一开始定好就不变**，只有状态随证据推进。
- **判定只看当前这一片**：计划模式下，每轮判定问的是「**当前里程碑完成了吗**」，不是「整个目标完成了吗」——问题窄，判定就准。完成就自动推进到下一片，没完成就继续当前片。
- **整目标完成 = 所有片都完成**（推导出来的，不单独问一次）。所以 agent 看不到后面还有哪些片也不会走偏：每轮续跑都附上**完整里程碑路线**（✅/▶/·）。
- **不动你的文件**：你 `@` 的那份只做只读引用。只有你在回复里**明确要求**把某项结论同步过去，pi 才会改它。改文件不会移动球门；要换路线就再 `/goal plan` 一次。
- 规划失败（读不到文件 / 返回不可解析 / 出错 / 中断）**不启动**，直接告诉你。

## 设计上的取舍

- **判定基于证据**：要求 transcript 里有实证（文件改动、命令输出、测试结果）。目标里写清验收标准，判定会准得多。
- **默认跟随会话模型**：判定调用用的是当前会话模型；想省钱可以在 `/goal model` 里换成便宜模型。
- **只读 transcript 尾部 40k 字符**：目标很长时前面的上下文可能被截断，所以续跑消息里每次都重申原始目标。
- **状态存在会话里**：以 `custom` 条目写进 transcript，不落额外文件、不发网络、不起进程。分支/恢复时状态自动正确。
- **不干预无目标会话**：没有活动目标时，扩展在所有事件上都是空操作。

## 结构

- `index.ts` — 循环接线与命令（单文件）
- `plan.ts` — 计划模块：规划提示词、解析、看板、里程碑推进、确认分类（纯函数，只有读文件有副作用）
- 依赖：只 import pi 自带供给的包（`@earendil-works/pi-ai`、`@earendil-works/pi-coding-agent`、`@earendil-works/pi-tui`）＋ `node:fs`

## 安装

作为 pi 包装（推荐）：

```bash
pi install npm:@ggbondex/pi-goal
# 或直接装 GitHub 上的源码：
pi install git:github.com:ggbondex/pi-goal
```

或手动放到用户级扩展目录（所有项目生效）：

```bash
ln -s "$PWD" ~/.pi/agent/extensions/goal-loop
```

改完在 pi 里执行 `/reload`。

## 测试

```bash
npm test          # 先 test/setup.mjs 复用本机已装的 pi，再跑两个测试
```

- `test/mock.test.mjs` — 用假 model registry 覆盖各分支（启动 / 续跑 / 完成 / 受阻 / 中断 / 上限 / 恢复 / 判定失败 / 停止 / 状态行 / **规划→确认→驱动→完成**），不发网络、不花钱。
- `test/plan.test.mjs` — `plan.ts` 的纯函数（解析 / 看板 / 里程碑推进 / 确认分类 / 文件路径）。
- `test/integration.test.mjs` — 在真实 pi 运行时里用假 provider 跑完整循环，验证续跑消息确实被下一轮看到。

`test/setup.mjs` 只是把本机已安装的 pi 包软链进 `node_modules/`，**不下载任何东西**；已存在的真实安装不会被覆盖。
